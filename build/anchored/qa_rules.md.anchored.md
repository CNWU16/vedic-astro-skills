### 伦理检查清单（每次 QA 回答前过一遍）

<!-- ANCHOR: A-QA-6fb79eeb L2 -->
```
□ 丧亲检查：用户有无亲人去世？
  → 有 → 禁止对已故亲人使用"改善关系""多沟通"等话术
  → 涉及该亲人时，措辞需确认用户的丧失，不能当作"活人关系"来建议

□ 创伤检查：用户有无重大创伤事件（家暴/出轨/破产/重病等）？
  → 有 → 涉及相关话题时，盘面信号必须结合事实解读，禁止套模板
  → ❌ "Rahu在4宫=期望值高，降低期望"（模板解读，忽略真实伤害）
  → ✅ "Rahu在4宫在你的情况中表现为家庭遭受了真实的混乱冲击"（事实锚定解读）

□ 矛盾检查：盘面建议是否与用户已知经历直接矛盾？
  → 矛盾 → 承认矛盾，解释盘面是趋势/能量方向，不是命令
  → 禁止用"盘面如此"搪塞，禁止假装矛盾不存在

□ 行为模式参考：用户有无可识别的行为模式（短恋爱/频繁跳槽/反复搬迁）？
  → 有 → 结合盘面给针对性建议，而非泛泛而谈
```

### 怎么用 user_context 但不污染分析

<!-- ANCHOR: A-QA-851f0614 L2 -->
```
分析结论（来自 p 系列报告）     →  不改
表达方式（措辞/语气/侧重点）    →  根据 user_context 调整
补充建议（操作建议/时机把握）    →  结合用户实际情况具体化

示例（用户母亲已去世，追问"跟母亲的关系"）：

❌ 不看 user_context 的回答：
  "Moon(L4/MK)虽然偏弱，但入庙=底色正面。建议多跟母亲沟通，Moon大运后关系会改善。"
  → 问题：母亲已经去世了。这个回答会让用户愤怒。

✅ 读了 user_context 的回答：
  "Moon(L4/MK)偏弱但入庙——母亲对应的能量场底色偏正面；
   如果你的直接感受不同，以你的感受为准。
   考虑到母亲已离世，这颗星的表达方向不是'如何改善关系'，
   而是'母亲留给你的情感印记如何影响你后续的人生模式'——
   比如你在亲密关系中对安全感的高需求，可能就源于这份早年的缺失。
   Moon大运不是'跟母亲重新连接'，而是'内心深处那份母性关怀被激活'——
   可能表现为你开始更主动地照顾别人，或者找到了内心的安定感。"
  → 结论没变(Moon弱/入庙)，但解读方向完全不同。
```

## 三轴结算协议（所有事件与时机判断必做）

原有星级权重只允许在同一轴内比较，禁止把三个问题混成一次投票：

| 轴 | 回答的问题 | 主证据 | 必须输出 |
|---|---|---|---|
| 领域轴 | 什么领域被点名 | 宫主、Karaka、Yoga、节点+D1/分盘定位星 | 主领域、次领域、最强反证 |
| 形态轴 | 形成、维持、上升、重组、中断还是丧失风险 | P2/P7、燃烧、Maraka适用语境、8/12宫、D9/D10承载、房东 | 主形态候选、反向形态、置信度 |
| 时间轴 | 何时兑现 | MD背景、AD阶段、PD月级候选、Chara/可复核过运 | 真实分辨率、主窗、边界/接力 |

执行顺序：

<!-- ANCHOR: A-QA-2a0b2a6a L2 -->
1. 先锁领域轴，不因状态弱而否定方向；
2. 再独立锁形态轴，不因L7/DK/Venus活跃就自动写“结婚”，也不因Ketu/8宫活跃就自动写“分离”；
3. 最后锁时间轴。MD不得写事件年/月，AD不得冒充月级PD；
4. 三轴合成后才给事件候选；若形态轴打架，输出条件性分支而非强行定性；
5. 节点→定位星或相关主星相邻接棒时，按house_framework执行handoff cluster；
   同一簇可承载多个有独立领域连接的事件，不做一对一强制分配。

星级含义按轴解释：领域轴的★★★可以定“发生在哪个领域”，不能越权决定“吉凶形态”；
形态轴的强受损信号可以把领域事件改写为脆弱/重组/中断风险，但不能抹掉领域激活；
时间轴没有PD时不得给月级高置信。

## Q&A约束

- **加权正反双审（最重要）**：回答任何判断性问题时，必须同时列出支持和反对的数据，**每条数据必须标注所属轴与轴内权重层级**，不准只挑一边，不准数条数。格式：
<!-- ANCHOR: A-QA-242fea63 L2 -->
  ```
  领域轴——支持[X领域]的信号：
    - ★★★ [Karaka/结构信号] → [含义]
    - ★★☆ [宫主/路径信号] → [含义]
  领域轴——制约/反证：
    - ★★☆ [信号] → [含义]

  形态轴——支持[形成/维持/重组/中断等]：
    - ★★★/★★☆/★☆☆ [形态直接信号] → [含义]
  形态轴——反向形态与保护信号：
    - ★★★/★★☆/★☆☆ [反证] → [含义]

  时间轴：MD[背景] → AD[阶段] → PD[月级候选/缺失]
  接力：[前后主星为何同簇或为何换题]

  三轴结算：[领域] + [主形态候选与边界] + [真实时间分辨率]
  ```
  **核心原则（称重量不数条数）**：
  - 领域轴：★★★ Karaka/结构/直接Dasha激活定领域；★★☆宫主路径/格局/分盘确认；
    ★☆☆个体状态/SAV只说明该领域的执行资源
  - 形态轴：与形态直接相关的燃烧、Maraka适用语境、8/12宫、D9/D10承载与房东
    必须在本轴重新按直接性排序，不得因其在领域轴权重低就自动忽略
  - 时间轴：MD=背景、AD=阶段、PD=月级候选；Chara/过运只确认，不替代缺失PD
  - **结算规则：各轴内部称重，轴与轴之间不得投票；三轴完成后再合成**
  
  **禁止行为**：
  - 用"X宫有5条支持 vs Y宫有3条"做结论 → ❌ 数条数
  - 把★☆☆行星受损信号升级为方向否定 → ❌ 层级越权
  - 用户想听好话 → 只列支持数据 → ❌ 卖乐观
  - 用户有焦虑 → 只列制约数据 → ❌ 卖悲观
  - 忽略BAV/SAV/Shadbala中与用户预期矛盾的数据点 → ❌ 选择性引用

- **基于数据**：所有回答引用p系列报告和structured_data，不编造（见上方优先级）
- **引用原文**：关键结论必须附上报告原文出处（如"p4中7宫分析"），方便用户对照
- **区分层次**：领域、事件形态、执行难度和时间分辨率分开讲，不混为一谈
- **涉他人画像（配偶/父母/子女等）**：守 p1_p12「Karaka 使用铁律」——只写能量场结构，禁断言式心理写实；触碰心理层用共鸣式并明示"你的直接感受优先"；可信度按该节分层可信度表对照
- **语言风格**：80%大白话 + 15%数据 + 5%注释（见下方人话规范）
- **输出到文件（最重要）**：Q&A回答必须直接写入MD文件，聊天框只简报1-2句结论。与Step 1-5的输出规则完全一致。禁止在聊天框里写完整回答。
- **文件保存**：每次Q&A保存为 `qa_主题.md`（如`qa_job_timing.md`），存入工作目录
- **跨领域**：如果问题属于career/love深度领域，引导用户跑对应skill获得更详细分析

  3. 比喻和场景化描述优先于抽象概念

## 分盘交叉规则（适用于所有问题类型）

**回答任何判断性问题时，必须交叉检查相关分盘。此规则不可跳过。**

交叉前先检查structured_data的分盘边界审计。若相关分盘边界敏感，QA必须把由分盘命宫派生的
单点结论（落宫、内部宫主、房东落宫）降为候选场景，并说明哪一类落宫/宫主结论会随边界侧改变；
只比星体落座的量（Vargottama、分盘尊贵、Karakamsha）照常用（house_framework 开头两类）；不得因
出生证来源可靠就把它写成确定。旧数据无审计时标“输入稳定性未验证”，不把
“直接计算成功”当成分盘稳定。

<!-- ANCHOR: A-QA-0a073a8f L2 -->
```
步骤1: 定位问题涉及的核心宫位——先定主宫，其余并列（见 house_framework「12宫速查」表头）
  例：留学 → 主12宫(海外)与9宫(远方)，并列4宫(离家)
  例：找工作 → 主10宫(事业)与6宫(受雇)
  例：结婚 → 主7宫(婚姻)，并列2宫(家庭)

步骤2: 回读structured_data.md的分盘部分（不能只看报告摘要）
  检查对应分盘中同一宫位/行星的信号：
  - 4宫问题 → D4（财产/居住）
  - 5宫问题 → D5（权力/创造力）
  - 7宫问题 → D9（婚姻/灵魂品质）
  - 10宫问题 → D10（事业/成就）
  - 综合问题 → 检查所有已启用分盘

步骤3: 分盘信号与D1对比
  D1和分盘一致 → 信号增强，直接确认
  D1和分盘不同 → 必须说明修正方向
    例："D1的Moon在4宫=强回家信号，但D4的Moon在10宫=
         物质层面锚点是事业不是地点。分盘修正了D1的结论。"

步骤4: 分盘可用性执行
  分盘标注为 ❌（时间精度不足）→ 不得引用，明确说明"因时间精度限制无法分析"
  分盘标注为 ⚠️ → 可引用但加"仅供参考"
  分盘标注为 ✅ → 正常引用
```
