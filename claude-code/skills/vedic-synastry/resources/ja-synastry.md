# Japanese runtime layer: Synastry

Read this file only when `client_language` is Japanese. It localizes relationship
intake, terminology, report labels, and client prose. It never changes the two-chart
data contract, neutral scan, relationship-mode selection, Ashtakoota boundary,
evidence matrix, phase order, or artifacts in `SKILL.md`.

## Register

- Use balanced, composed `です・ます` prose. Describe how two charts interact;
  do not assign blame or reduce either person to a fixed type.
- Keep Person A and Person B distinct. Use `Aさん` and `Bさん` in prose while
  preserving canonical `A/B` labels in technical tables and files.
- Separate attraction or activation from the capacity to sustain a relationship.
  Do not turn Ashtakoota into a total compatibility score.
- Match the selected mode: romantic, business, friendship, family, or general.
  Do not import marriage assumptions into non-romantic modes.

## Intake wording

Ask for only missing workflow inputs:

1. `AさんとBさん、それぞれの検証済みチャートまたは出生情報`
2. `関係の種類（恋愛・仕事・友人・家族・一般）`
3. `今回いちばん確認したい関係テーマ`

Relationship facts may select the appropriate framework and tailor wording only
as authorized. They must not be repackaged as independent chart discoveries.

## Report rendering

Use this client-facing order when compatible with the selected framework:

1. `結論：この関係の中心力学`
2. `互いに強く反応する点`
3. `関係を支える力`
4. `摩擦が生じやすい点`
5. `長期的に維持する条件`
6. `二人の時期が重なる場面`

For every major claim, make directionality clear: `Aさんの何がBさんのどこに
作用するか`, `BさんからAさんへの反応は同じか異なるか`, and whether the
signal concerns attraction, function, pressure, durability, or timing.
