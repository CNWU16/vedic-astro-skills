# Vedic Skill Suite｜Codex执行增强分享包 v1.1.0

这套补丁不会修改任何Vedic skill文件。无人另行指示时，标准运行仍以所选
`SKILL.md` 为唯一方法与流程真源。

这不表示Vedic skill的方法本身有问题。同一份 `SKILL.md` 在能够正确调用模型综合判断
的其他Agent环境中，可能不需要这层兼容增强。本包的定位是让 Codex 忠实执行
既有方法、并在需要AI综合判断的地方不退化成机械计分。

校准模块已对齐最新版 `vedic-rectifier` 的三类证据：结构硬证据、时间硬证据与
软证据。旧版“事件×Dasha与特质×结构两腿平权”已经退役；补丁保留候选级专家
综合，但专家综合只能在skill仍允许结算的候选中工作，不能绕过结构淘汰、硬证据
门槛、固定裁决定序、欠定通道、两点法或分盘精度。

它是一层专门为Codex准备的执行规则，解决印占工作中最常见的几类问题：

- 没有完整读取 `SKILL.md`，凭印象执行；
- D1、D9、D10或其他阶段跳步、乱序；
- 擅自扩大出生时间范围或候选池；
- 只验证当前最喜欢的候选，没有重算完整矩阵；
- 根据 `user_context` 反向寻找盘面解释，导致结论过拟合用户经历；
- 找到一个支持点就提前停止，没有扫描反证和其他候选；
- 本机同时安装标准版与Pro版core时没有先选版，或把两版同名报告文件混在一起；
- 把skill流程当成不可违抗的封闭程序，拒绝操作者明确要求的重走、覆盖或重置；
- 报告堆满术语，或者只剩缺乏解释的短句，无法用于真实咨询。
- 为了显得谨慎反复写“仅供参考／结合实际／权衡利弊”，最后没有明确占星判断。
- 分析师稿充满“结构、承载、能量、课题”等抽象词，却没有说清现实中到底会
  发生什么，也没有足够展开的人话和能够被客户记住的盘面判断。

## 这个分享包提供什么

### 1. Vedic全流程执行纪律

全局 `AGENTS.md` 只作为精简路由器：强制Codex完整读取所选Vedic skill，
公开当前阶段、授权范围、候选集合、本阶段输出和转场条件，再按任务加载UC、
校准、盲问、客户表达、普通QA、产物或分析师剪辑模块。操作者没有另行指示时，严格按照
skill规定的顺序执行。

如果本机同时安装 `vedic-core` 与可选的 `vedic-core-pro`，全新core本命分析会
在第一个core产物写入前选择版本：操作者已指定时直接执行，未指定时询问一次。
没有安装Pro的电脑不会显示Pro选项。选定后整次分析、续跑、QA、盲问、分析师
剪辑和HTML都继承同一报告谱系，不会把两本 `SKILL.md` 或两套p文件静默拼接。

Pro不需要独立补丁包。标准版和Pro版共享UC防火墙、客户表达、产物路由与其他
执行护栏；Pro多出的身份定锚、格局、动态预测、专题和生命蓝图仍由Pro自己的
`SKILL.md`规定，统一补丁只在对应阶段按同一原则执行，不复制出第二套真源。

它不会静默重新定义占星阈值、候选规则或置信度标准。标准运行以所选
`SKILL.md` 为准；操作者明确要求改变当前任务时，则按操作者指定的方式执行，
但不会把该次指令写回skill本体。

补丁本身不发明机械配额。除非数字来自skill、操作者、真实数据分辨率或安全边界，
问卷轮数、候选截断数量、章节段落、主线数量、正文比例、建议条数和观察周期都
根据当前证据与任务需要弹性决定。弹性不会删除skill明确要求的完整矩阵和转场检查。

当skill明确要求AI解读、多维判断、综合或最强信号选择时，必做扫描、表格与清单
仍全部完成并可复核，但它们是专业判断的输入，不是机械数勾的投票器。Codex会在
skill允许的候选中比较跨信号收敛、盘面特异性、语义一致性、可证伪性和基础率、
最强反向信号，以及结论具体度是否匹配数据分辨率；这些不会被换算成新分数。

这会直接改善reader正向验前事的预测选择：先完整扫描A–H及所有规定维度，再由
整体证据选择最有验证力的陈述，而不是挑勾最多的一行。但用户反馈后的准／部分准
／不准、命中率、R1限制和后续路由仍严格按 `vedic-reader` 执行，AI不能用综合
判断重写反馈结果。其他skill明确规定的数值、冲突跳过和阶段门槛同样不受影响。

### 2. 操作者最终调度权

Skill是无人另行指示时的标准流程，不是Codex拒绝操作者命令的理由。在系统安全、
权限和客观技术条件允许的范围内，操作者可以要求补充、重走、跳转、替换或完全
重置当前流程，也可以指定当前运行的计分、解释、停止条件和产物处理方式。
证据使用方式也可由操作者为该次任务明确指定。

操作者同时决定新旧流程的关系：

- 作为补充时，两轮按指定用途共存；
- 要求覆盖时，旧流程受影响的评分、结论和下游产物作废，新流程成为唯一依据；
- 要求重置时，从指定节点重新开始，只保留操作者允许继承的材料。

Codex不得强制把覆盖性重跑降格成“额外变体”，也不得反复用旧skill流程进行
免责声明。已经看过的反馈不能被虚构成“从未看过”，但这项事实边界不能成为
拒绝重跑、重新计分或采用新结果的理由。

### 3. UC证据防火墙

`user_context.md`、聊天中的个人经历、既往反馈和报告中的现实事实，
不能替代盘面证据。

这套规则把“记录／写入、读取、盘面推理、咨询映射”分成四个不同动作：

- 写入事实只是行政记录，不自动把事实变成盘面证据；
- 读取权限严格服从所选skill的当前阶段；
- 允许读取不等于允许照UC生成、选择或加权盘面结论；
- 盘面标准锁定后，才可用允许读取的UC做伦理检查、表达调整、现实选项映射、
  行动建议或已确认事实的后置核对。

盘面判断必须能够在删除UC后独立复现。补丁既不扩大也不收紧skill明文规定的
UC读写权限，修正的是Codex在“已经允许读取”之后容易照本宣科的问题。

在reader正向验前事中，已知感情状态不会把整个感情领域关闭。Codex必须先从
盘面独立锁定F类感情时间窗及盘面支持的方向，之后才可用单身、恋爱、已婚、离异、
分居或丧偶等状态调整生命周期措辞；状态不能移动窗口、抬高弱信号或凭空决定
结婚／离婚。H类只负责猜未知的当前状态。只知道转折存在但不知道日期时，仍可
验证盘面推出的时间窗；具体事件与日期已经知道时，只作已知事实核对，不计独立
R1命中。

在Q&A选择题中，Codex先锁定盘面评价标准，再按同一标准映射现实选项。
Offer A／B的事实不同可以合理改变最终推荐，但不能倒过来修改盘面标准和权重。

最新版core增加了严格只读的措辞落点校订：标准版Step 4.5、Pro版Step 6.5只在
全部盘面结论锁定后读取 `user_context.md`，并且只修改skill点名的客户正文。
评级、窗口、领域、配偶画像主形态／次选／来源方向、Yoga、Dasha、数据表和上游
技术文件全部锁定不动；敏感标签只在内部用于伦理检查，不能在报告中复述，也不能
把已知经历包装成预测或盘面发现。

这样既能减少“照着用户经历说”的确认偏误，也不会把正常咨询变成没有人情味的
匿名数据分析。

### 4. 校准执行质量审计

针对Codex在时间校准中容易机械累加总分、忽略候选区分度、生成巴纳姆式特质题、
误用代表点Dasha以及混淆“工作盘／最佳估计／确认结果”的问题，AGENTS会在
`vedic-rectifier` 激活时先加载精简执行罗盘，再只在结算、出题和精调区间阶段
读取对应专项模块。这样保留完整能力，而不让所有补救规则在每个阶段同时占用注意力。

它保留 `vedic-rectifier` 的阶段顺序、候选范围、原始矩阵、数值计分、两点法、
分盘精度和文件名，并完整继承三类证据与固定裁决定序。结构硬证据只来自
`event_house_map` 静态事实表，必须事前登记、只计候选变化字段；结构淘汰只有
在客观事实已确认、映射行允许淘汰、全部相关指征同向否定三个条件同时满足时
才能发生。时间硬证据继续用带日期事件×Dasha。关系质量、家庭氛围、性格、自我感、
职业风格，以及静态事实表未授权的事实都属于软证据。

结构硬证据与时间硬证据都可用于裁决，但顺序是先结构剪枝、再比较Dasha与硬分。
软证据仍可显示支持度和帮助成文，但不得打破硬证据平局、淘汰或复活候选、改变
硬分或提升置信度。硬证据在skill翻转门槛内打平、只剩软证据有差时，结论必须
保留欠定，优先请求出生记录等外部硬锚，不能再用特质问卷制造赢家。

原始总分仍完整保留并照常测试skill门槛，但“原始分领先者”不再被自动等同于
“当前最佳估计”。差分审计和全候选反证之后、正式结算之前，Codex必须暂时把
总分括起来作为一项已审计结果，再把每个候选当作完整解释假设进行专家综合：
比较其跨独立领域的解释覆盖、Dasha与结构的一致性、候选特异性、最强反证、
需要多少临时补救或事后圆盘，以及移除共同、相关、边界和低精度噪声后的稳健性。

专家综合不是分数已经决定之后附加的评语，也不是新建“质量分”或另一套隐藏
门槛。每个判断都要落回具体硬证据区分行、盘面结构与最强反证；但它不能推翻
结构淘汰、把软证据升级成硬证据、移动固定裁决定序，或把skill要求的欠定改写成
确认。这个要求只作用于 `vedic-rectifier`，不会改变core、普通验前事、盲问或
其他Vedic skill。

模块还增加了明确的停止门：补问前必须先用已有材料测试结算；原始矩阵达到skill
确认门槛时，立即确认当前层并进入下一阶段。证据质量
审计不得另造“去重分／有效分／独立净分”推翻canonical总分。问卷不设机械轮数：
每轮后先全候选复算；只有仍未结算、且下一轮能检验一个明确、独立、可能改变排序
的差异时才能继续。设计含糊或无区分力的问卷记为零信息，可以重新设计，不会因为
“已经问过一轮”永久失去补问机会。新证据按全候选增量复核，没有翻转或数据源
失效就不重开已确认层。

校准问卷可以读取skill授权的UC：已知经历可以作为用户熟悉、容易回答的现实场景。
限制针对的是“根据已知答案反向设计候选映射”和“把旧事实包装成新的独立命中”，
不是禁止在校准中使用UC。Step 5盘外验证所要求的未参与校准领域，只约束样本外
验证，不会被提前套用到Step 3c或D9/D10候选区分问卷。

互斥题本身也有题前质量审查。D1只对不同上升星座出题，同一D1里的Dasha子窗
不会被伪装成两个结构对象。审查不是机械全项打勾：答案泄漏、无候选区分力、
明显诱导和纯重复属于无效；具体性、双真风险、相关性和字母平衡则按信息价值
修写或分为独立有效、相关有效、探索性弱信号。具体单次经历和有实例支撑的反复
模式都能作为回答依据。批次边界从操作者完整意图判断：明确只做一批就结算后停，
已经授权持续校准则可按结算门继续，不从孤立措辞机械推断。

校准补问必须先标明它属于结构硬、时间硬还是软证据。结构硬题必须有静态事实表
授权、事前登记与候选变化字段；时间硬题保留用户真实能提供的日期精度。A/B特质题
仍可用日常语言记录辅助符合度，但它是软证据，不能被描述成能够解决硬证据欠定。

补丁会拦截“形式上互斥、实际上答不了”的题：不能要求用户重建日期、把多段异质
关系平均成一种性格、猜隐藏动机、解因果链，或靠“哪个先发生／哪一步不可缺”
人为制造排他性。一个结构轴无法翻译成明显问题时，应换真正不同的根本结构轴，
不能在后续轮次反复改写同一微妙机制。

硬证据打平时先找外部硬锚，其次补真正能改变排序的硬事实或带日期事件。一个事实
不会因为“客观”二字自动成为结构硬证据，必须命中skill的静态事实映射规则。三个
以上候选可以采用单候选对候选组或两两淘汰；候选映射和盘面依据在反馈前锁定，
但不会提前展示给答题者。

问卷没有固定轮数。无法作答的题或整批在反馈前撤回，记为零信息，不计作候选
冲突；只要当前层仍未结算，仍可换一个真正不同、可辨认的结构轴继续。追问更精确
月份前则必须先证明该日期范围跨越了候选特有的Dasha或原始计分差异，单纯想要
“更精确”不能成为反复追问月份的理由。

软证据不是决胜票：完整矩阵、事前锁定、反巴纳姆、全候选反证和区间两点法仍是
必需项。固定题数、全选A/B或一边倒的软反馈本身不会自动确认。D1确认只锁定
上升星座，后续仍按D9、D10逐级缩小时间，不能越级声称分钟精度。

### 5. UC隔离盲审

用户要求盲问或全量重判时，Codex会自动读取完整盲审SOP。

当前随包协议为v1.3：先让全部决策相关候选进入MD/AD矩阵，再锁定所有需要
月／日级分辨率的PD合格候选并统一局部下钻；“全量”不再被误解为把729行PD
全部送入模型上下文。局部PD依赖新版 `vedic-calculator` 的原生三级运与
`scripts/dasha_query.py`。由于本包不含skills，接收方缺少兼容版本或PD校验失败时
必须降级到AD窗口，禁止比例近似或只给当前领先候选读取PD。

默认模式允许UC存在，但禁止UC参与结论、候选排序、权重、停止点和置信度。
问题定义下的全部决策相关候选必须进入矩阵；年度排名题才要求范围内每个公历年
逐一进入。找到强点后仍要扫描到终点，再比较所有仍有实质竞争力的领先候选，
不预设固定人数并保留并列。

如果答案已经出现，仍可执行回溯式全量盲审，但不能把结果包装成独立盲测命中。
只有需要证明答案事前完全未知时，才使用新任务和净化数据包执行防泄漏盲测。

### 6. 温柔而坚定的客户表达、产物路由与普通QA

标准版与Pro版Core的解释性正文都会读取统一的 `vedic_client_voice.md`。前面的
技术报告仍保留Skill要求的矩阵、参数、反证、置信与来源，但不再被当成模型私有
草稿：每个技术单元都要解释这组数据意味着什么，术语首次出现时翻译，普通用户
跳过表格也能理解结论，分析师查看表格仍能完整复核。真正改变结论的限制只说明
一次，不把每个段落写成免责声明。

Core完整报告本身也分工清楚：行星、分盘、格局、宫位、预测和附录负责保存精确
技术依据；标准版最后的 `p5a_life.md`／`p5b_life.md` 与Pro版最后的
`p6a_life.md`／`p6b_life.md`／`p6c_blueprint.md` 是默认主要交给客户阅读的核心
正文。这些阶段自动读取 `vedic_core_life_rendering.md`，先锁定上游结论、反证和
时间分辨率，再把各板块写成一条能读懂、能追溯、彼此相连的人生主线。它不降低
精度、不删反证、不另建产物，也不等同于后期分析师剪辑。正文写完后，标准版
Step 4.5／Pro版Step 6.5再按skill允许的文件范围做局部措辞校订，只改表达与落点，
不改任何盘面结论或技术数据。

补丁区分技术主报告、分析师完整报告、普通单题QA和盲问全量扫描产物。一个
聚焦问题只有在所选skill已经满足自身QA入口条件后，才进入普通QA；不会因为
问题很短就跳过尚未完成的正式分析，也不会把Prashna或校准误改成core QA。

普通QA不需要激活完整分析师剪辑模式。它保留skill规定的文件名、矩阵、正反双审、
分盘交叉和证据表，只调整客户成文顺序：

1. 先用完整自然段直接回答；
2. 再解释盘面支持、最强反证和置信度；
3. 描述最可能的落地方式和真正影响它的条件；
4. 只有有价值时才给盘面相关的下一步。

术语可以保留，但必须在同一句中翻译；禁止电报式参数链、重复转述用户经历，
也禁止用“结合实际、谨慎权衡、多沟通”等泛化话术代替占星回答。不利信号和真实
不确定性仍保留，但按实际影响等比例表达。

HTML只应是选定Markdown的呈现副本。补丁要求执行前核实打包工具会读取哪些文件，
避免把目录中所有QA或其他报告层悄悄混入本次成品。

### 7. 咨询式整合模式

当 `vedic-core` 或 `vedic-core-pro` 完整技术报告已经生成，可以显式激活咨询式整合模式，
输出一份分析师剪辑版完整报告。

这个模式不是Q&A，也不围绕某一个临时问题作答。它把p系列、十大板块和技术附录
作为底稿，重新建立全盘主线、前事核对、领域联动、过去—现在—未来时间线、
关键反证和盘面相关建议，形成一份能够直接交给客户阅读的完整报告。

它是core完成后的独立文档编辑任务，只负责报告综合、轻重剪辑和人话表达，
不重跑core，也不修改盘面结论、Dasha计算或UC证据权限。

执行时先识别并继承既有报告谱系。标准版从p1至p4和appendix锁定纯盘面底表，
再读取p5a/p5b；Pro版从p0、p2至p5c技术文件和appendix锁定底表，再读取
p6a/p6b/p6c。内部继续分开盘面置信、前事核对和UC适配；客户成品不机械展示
可信度分类，而是先给温柔坚定的总判断，只对真正受限的结论集中说明边界。

随包分析师协议v2.3默认采用长篇人话，而不是省流短句：每个重要判断都要落到
可观察的现实表现，讲清形成机制、时间变化、领域联动和实际意义。它会清理不改变
结论的免责段和连续缓冲语；在盘面真正形成独特综合判断时，保留准确、具体、能够
打动人的金句，但不制造宿命口号或可套给所有人的鸡汤。

## 适合谁

- 已经在Codex中使用 `vedic-*` skills 的个人用户；
- 需要为不同客户建立独立任务和工作目录的咨询者；
- 希望减少跳步、越界、确认偏误和事后解释的使用者；
- 希望保留技术依据，同时让报告真正能够用于咨询的人。

## 不包含什么

- 不包含Vedic skills本体；
- 不包含可选的 `vedic-core-pro` skill；接收方必须另行安装后才会出现Pro选项；
- 不提供排盘数据或客户案例；
- 不替代 `vedic-reader`、`vedic-rectifier`、`vedic-core`、
  `vedic-core-pro` 等正式流程；
- 不能让已经看过答案的模型在数学意义上真正“忘记”答案；
- 不能覆盖更高优先级的系统规则或对方已有的项目级指令。
- 不能保证已经打开的Codex任务自动重载后来安装或修改的全局指令。
