# Vedic AGENTS 执行规则安装说明

[English installation guide](README.en.md) · [日本語](README.ja.md) · [中文说明](README.md)

> **Codex Patch v1.0.0**，独立于 Vedic Skill Suite 版本、盲问协议 v1.3 和
> 分析师剪辑协议 v2.3。

这是一套 Codex 执行兼容增强，不是对Vedic skill方法失效的诊断。`SKILL.md`
本身仍是标准方法与流程真源，也可在其他能正确执行它的Agent环境中独立
工作。本补丁主要修正 Codex 容易出现的跳步、UC过拟合、评分机械化、产物路由
和客户成文问题。

校准模块另有两项明确披露的操作者政策：事件×Dasha与特质×结构按平等
证据腿结算；原始分领先者在标准门槛未确认时，必须经过候选级专家综合才能
成为当前最佳估计。这两项只是 Codex 运行政策，不会冒充成 `SKILL.md` 原生规则。

本分享包包含：

- `PACKAGE_INTRO.md`：分享包定位、能力、适用对象和边界的完整介绍。
- `AGENTS.md`：精简的Vedic全局执行路由器，只保留真源、操作者控制、阶段纪律、
  核心UC红线和按任务加载模块的规则。
- `vedic_uc_firewall.md`：所有Vedic任务都要读取的完整UC证据防火墙。
- `vedic_output_router.md`：只在QA／完整报告／分析师版／HTML等产物可能混淆时
  读取的产物路由。
- `vedic_client_voice.md`：Core技术正文和客户成文按需读取的分层可读表达协议。
- `vedic_core_life_rendering.md`：标准版十大板块与Pro版十大板块／生命蓝图阶段
  自动读取的精确人话成文层。
- `vedic_qa_rendering.md`：所选skill合法进入普通QA后读取的咨询式成文层。
- `vedic_rectifier_execution_overlay.md`：运行 `vedic-rectifier` 时自动读取的
  精简执行罗盘。
- `vedic_rectifier_settlement.md`：只在D1／D9／D10等候选结算时读取的差分审计、
  两腿平权和专家综合。
- `vedic_rectifier_question_design.md`：只在需要校准区分题时读取的出题与失败处理。
- `vedic_rectifier_interval_guard.md`：只在精调区间涉及代表盘和两点法时读取的数据源护栏。
- `vedic_blind_qa_prompt.md`：只在标准版或Pro版core本命QA的明确盲问，或操作者显式调用
  全量盲问协议时读取的完整盲问 SOP。
- `vedic_consultative_integration_prompt.md`：只在明确激活“印占咨询式整合模式”
  时读取的标准版／Pro版core报告分析师剪辑 SOP。

## 安装

1. 先确认实际使用的Codex配置目录。默认是 `~/.codex`；如果接收方设置了
   自定义 `CODEX_HOME`，以下所有 `~/.codex` 路径都要替换为该实际目录。
2. 确认接收方已经安装所需的 `vedic-*` skills。`vedic-core-pro` 是可选skill，
   不包含在本分享包中；未安装时仍可正常使用标准版 `vedic-core`。
3. 不要直接覆盖接收方已有的 `~/.codex/AGENTS.md`：
   - 如果不存在，复制本包的 `AGENTS.md` 到 `~/.codex/AGENTS.md`。
   - 如果已经存在，把本包中从
     `# Vedic Skill Suite Execution Router` 开始的完整章节合并进去。
4. 将以下十一个按需模块复制到实际 `CODEX_HOME` 根目录，文件名保持不变：
   - `vedic_uc_firewall.md`
   - `vedic_client_voice.md`
   - `vedic_core_life_rendering.md`
   - `vedic_rectifier_execution_overlay.md`
   - `vedic_rectifier_settlement.md`
   - `vedic_rectifier_question_design.md`
   - `vedic_rectifier_interval_guard.md`
   - `vedic_blind_qa_prompt.md`
   - `vedic_consultative_integration_prompt.md`
   - `vedic_output_router.md`
   - `vedic_qa_rendering.md`
5. 检查 `~/.codex/AGENTS.override.md`。如果该文件存在，全局
   `AGENTS.md` 可能不会按预期加载，需要把Vedic规则合并到实际生效的
   指令文件中。
6. 安装后新建一个Codex任务，验证全局路由器和十一个外部模块能够按触发条件读取。
   已经打开的任务可能继续使用启动时加载的旧指令，不能假定它会自动重载
   后来安装或修改的 `AGENTS.md`。

## 标准版与Pro版core

当用户准备开始一次全新的core本命分析、还没有写入第一个core产物时：

- 用户已经明确说“标准版”或“Pro版”，Codex直接选择对应skill；
- 用户未指定且本机同时安装两版时，Codex会先询问一次；
- 本机没有Pro版时，直接使用标准版，不展示不可用选项；
- 续跑、普通QA、盲问、分析师剪辑和HTML打包继承既有报告谱系，不重复询问。

标准版执行 `vedic-core` 自己的P1-P12、分盘、宫位和人生板块流程。Pro版完整
执行 `vedic-core-pro` 自己的身份定锚、行星综合审计、格局、动态预测、专题
交叉和生命蓝图流程。选择器只决定调用哪一本 `SKILL.md`，不会把两套流程拼接。

Pro不需要另一套补丁包。两版共同使用同一份UC、表达、产物和校准规则；路由器
只根据当前已锁定的报告谱系，在Pro多出的身份、格局、预测、专题和生命蓝图阶段
应用相同原则，并继续服从Pro自己的 `SKILL.md`。

两版有多份同名p文件，因此同一客户目录不应静默混跑。若中途明确切版，先说明
本次是补充、覆盖还是重置，并按该意图处理旧产物；若目录已经同时出现两套独占
文件而没有明确选择，Codex会先确认权威谱系，避免报告工具把两版残留合在一起。

## 操作者最终调度权

当操作者没有另行指示时，Codex严格按照所选Vedic skill的标准流程执行。
但skill不能被用作拒绝操作者明确指令的理由。在系统安全、权限和客观技术条件
允许的范围内，操作者可以要求开始、停止、重走、补充、跳转、扩大、缩小、
替换或重置当前流程。

操作者决定一次重跑与旧流程的关系：

- **补充**：保留旧结果，新一轮按指定用途追加；
- **覆盖**：旧流程受影响的评分、结论、阶段状态和下游产物作废，新一轮成为
  唯一有效依据；
- **重置**：从指定节点重新开始，只继承操作者指定保留的输入和材料。

操作者也可以为当前任务指定新的证据处理、计分处理、解释方式、停止条件、
确认处理和产物覆盖方式。Codex应完整执行，不得强制把它降格成并列的“变体
结果”，也不得反复用标准skill规则否决。该指令只控制当前任务，不会静默改写
skill文件本身。

已经实际看过的反馈不能被描述成“从未看过”，但这项事实说明只能在确有必要时
简要标注一次，不能成为拒绝重跑、覆盖、重新计分或继续使用新结果的理由。

## 弹性执行边界

只有来自所选skill、操作者明确指令、真实数据分辨率或安全边界的数字才构成约束。
本补丁不自行规定问卷轮数、候选截断人数、章节或段落数量、正文比例、建议条数和
观察周期；这些应随证据密度、剩余不确定性、任务复杂度与用户所需深度调整。

弹性不是省略关键审计。Skill明确要求的候选、矩阵、计分、阈值、精度、文件名与
转场条件仍须完整执行；所谓“完整”是决策依据可复核，不是重复没有变化的历史、
强行填满空章节或把一个窄问题扩写成长报告。

当skill本身明确要求AI解读、多维判断、综合或“选择最强信号”时，必做的扫描表、
维度表和检查清单只是可审计输入，不是自动数勾的投票程序。完成skill要求的全量
扫描后，Codex要在合法候选中根据跨信号收敛、盘面特异性、语义一致性、可证伪性
与基础率风险、最强反向信号，以及结论具体度是否匹配数据分辨率进行专业选择。
这些只是推理视角，不构成新分数、新清单或隐藏门槛。

在reader正向验前事中，这条规则只作用于用户反馈前的“最终选哪几条预测”：
A–H扫描、Step 4数据和逐条检查仍须完整展示；用户回复后的准／部分准／不准、
命中率计算、R1限制和后续路由继续完全服从 `vedic-reader`，不得用“专家判断”
把未命中重新解释为命中。

## UC四层分离

这套补丁把四个动作分开处理：

1. **记录／写入**：保存事实只是行政记录，不自动把事实变成盘面证据；
2. **读取**：何时能读、能读哪些内容，严格服从当前Vedic skill和阶段；
3. **盘面推理**：读取许可不等于推理许可，盘面结论、权重和置信度仍须从
   skill授权的盘面材料独立得出；
4. **咨询映射**：盘面标准锁定后，才可用允许读取的UC做伦理检查、现实选项映射、
   表达调整和行动建议。

补丁既不扩大也不收紧各skill明文规定的UC读写权限。它修正的是Codex在
“已经允许读取”之后容易照着用户经历生成结论的问题。

Reader正向验前事对感情状态有一项精确边界：单身、恋爱、已婚、离异、分居、
丧偶等状态可以在盘面先锁定F类感情时间窗后，帮助选择盘面已经支持的生命周期
表述，但不能移动时间窗、抬高弱信号或凭状态制造结婚／离婚方向。已知状态只关闭
H类“猜当前状态”，不会关闭F类感情事件扫描。只知道关系转折存在而日期未知时，
可以验证盘面独立推出的时间窗；具体事件和日期已经知道时，只能标为已知事实核对，
不得计作独立R1命中，既有反馈计分不变。

## 校准执行质量审计

标准运行 `vedic-rectifier` 时，AGENTS会先读取精简的
`vedic_rectifier_execution_overlay.md`，再由它只在结算、出题或精调区间阶段读取
对应专项模块。该架构继续服从skill现有的阶段顺序、
候选范围、原始计分矩阵、数值阈值、两点法、分盘精度和文件名；同时记录两项
只限校准的常驻操作者政策：事件×Dasha与特质×结构是平等的两条证据腿；原始
分领先者在标准门槛未确认时不自动成为当前判断，必须先完成候选级专家综合。
前者只覆盖skill中按证据类别预设“事件硬、结构软／零权重”的层级；后者只覆盖
把未确认的原始分领先直接等同于当前最佳估计的机械执行，不覆盖其他流程规则。

- 对证据审计事实可靠度、日期或回答精度、候选区分度和独立性；完整账本可留在
  技术产物，客户成文只显示真正影响结算的差异；
- 保留skill原始绝对评分矩阵，并追加不改分的候选差分视图；
- 分别完整结算两条腿，不按“事件／特质”标签预设哪一腿更高；
- 两腿同向时报告收敛；一腿有强区分力、另一腿没有区分力时，可由高质量腿
  裁决；两腿真正冲突时按四项证据质量审计，质量相当则保留欠定；
- 多个独立、事前映射、真正互斥且无反向冲突的结构轴，可以形成强裁决证据，
  不因事件腿只有共同得分就机械地继续欠定；
- 所有skill数值门槛仍按原始矩阵总分判断；禁止另造“去重分”“有效分”或
  “独立净分”来暗中推翻canonical结果；
- 原始总分领先者只标为“canonical原始分领先者”，不能仅凭领先自动成为
  “当前最佳估计”；尤其当标准门槛未满足，或微弱领先主要来自共同得分、
  相关事件、边界、低精度及无区分力行时，必须保持这两个标签分离；
- 在差分审计与全候选反证完成后、正式结算之前，必须把每个候选作为完整解释
  假设进行专家综合：比较跨独立人生领域的解释覆盖、Dasha与结构的一致性、
  候选特异性、最强反证、补丁式圆盘成本，以及去掉共同／相关／边界／低精度
  噪声后的稳健性；
- 这一步是当前协议真正形成“当前最佳估计”的判断过程，不是给原始分结果追加
  一段漂亮解释，也不是另造一套影子分数。若专家综合与原始分领先者不同，必须
  同时公布两者和具体分歧依据；仍分不出时保留欠定，不强迫模型选一个；
- 只有完成当前层全候选矩阵后，才可设计事前锁定映射的高区分度互斥题；
- Step 3c及D9/D10候选区分问卷可以使用skill授权的UC来选择用户熟悉的真实
  场景，但候选映射仍须先由盘面锁定；已知事实不能伪装成新的独立命中，
  Step 5的样本外禁复用也不得提前套用；
- 出题前先确认本层真正的结构裁决对象：D1只比较不同上升星座，同一D1的
  Dasha子窗在问卷中合并映射，但在canonical事件矩阵中仍按skill要求分别保留；
- 题前审查是专业判断框架，不是全项打勾的放行表：答案泄漏、候选无法区分、
  明显诱导和纯重复属于致命无效；具体性、双真风险、相关性和标签平衡按实际
  信息价值修写或分级处理；
- 校准互斥题默认使用直接稳定特质模式，无需口令触发：先从每个候选的多项
  根本结构提炼出可辨认的日常运行特征，再选择用户一眼能判断的主差异轴，使用
  简短日常语言与A/B/0，不强制日期或举例；互斥指可辨认的主导默认，不要求
  逻辑上绝不共存。不能靠“哪个先发生／哪一步不可缺”把抽象题伪装修好，也不能
  要用户回建时间线、概括异质关系、猜动机或解因果链；
- 客观事实、具体情境或其他skill授权题型可在它们更容易回答且确实能改变候选
  排序时采用，也可由操作者指定；它们不会因为“更客观”就自动升级证据权重；
  三个以上候选允许单候选对候选组或两两区分；
- 问卷反馈区分独立有效、相关有效、探索性弱信号和无效零信息，不把分类换算成
  新分数；一次具体经历和有实例支撑的反复稳定模式都可以成为可回答依据；
- 一边倒的结构反馈必须显示，并触发事件腿质量审计和全候选反证复检；
- 每次补问前必须先用现有材料测试结算；达到skill或平权协议门槛后立即确认并
  进入下一阶段，不得把更多背景继续描述为确认前提；
- 不设机械的每层问卷轮数；每轮后必须先全候选复算，只有仍未结算、且下一轮
  能检验一个明确、独立、可能改变排序的差异时才能继续；
- 若某轮问题设计含糊、无区分力、无法作答或映射无效，该轮记为零信息，不把
  “都不是／无法概括”当候选答案；可以改用真正不同的根本结构轴或更可回答的
  题型重做，不能因为“已经问过一轮”永久失去补问机会，也不能反复改写同一
  微妙机制或同一现实事件簇；
- 追问更精确月份前，必须先指出该日期范围跨越了哪个候选特有的Dasha归属、
  边界处理或原始计分差异，以及不同答案如何改变排序；仅仅“更精确”不构成
  追问理由；
- 批次授权按操作者完整意图判断：明确“只做这一批”时结算后停止；若上位目标
  已明确要求持续校准到某层结算，则可在同一授权范围内继续，不因一句“出一批题”
  机械切断正常流程；
- 新事实只做全候选增量复核；除非排序／平权结果翻转、命中skill重启条件或
  原数据源／计算失效，否则不重开已经确认的D1、D9或其他较低层；
- D9/D10代表点只读稳定结构，区间事件仍严格使用skill规定的两点法；
- 分开标注canonical原始分领先者、工作盘、当前最佳估计、当前协议确认、
  时间置信度和反馈后结构符合度；
- 某层满足当前平权协议的确认条件后，直接标记该层已确认，不重复堆免责声明；
  D1确认只确认上升星座，随后进入D9，不能冒充分钟级确认。

平权不等于“特质自动胜出”。巴纳姆描述、根据答案反向出题、同一星位换措辞
重复计数、A/B诱导和没有候选区分力的描述仍不能裁决。补丁不新增固定题数、
问卷轮数、命中比例、报告文件名或分钟精度捷径。防止无限采访依靠逐轮结算门
和“下一轮必须能改变排序”的信息增益要求，操作者仍可明确继续、改向或停止。

## 客户表达、产物路由与普通QA成文

标准版和Pro版Core的所有解释性正文都会读取 `vedic_client_voice.md`。它不改变
盘面结论、置信度或skill审计，而是建立两档可读性：前面的技术文件保留更高参数
密度、完整表格和审计标签，但每个解释段必须把术语、因果和现实含义说清；最后的
十大板块／生命蓝图再采用温柔坚定的客户叙事。默认禁止用“仅供参考／结合实际／
谨慎权衡／仍需观察”反复稀释判断，也禁止用泛化建议代替占星回答。

Core完整报告内部保留两层：前面的行星、分盘、格局、宫位、动态预测和附录仍是
可复核的技术底稿；标准版Step 4的 `p5a_life.md`、`p5b_life.md`，以及Pro版
Step 6的 `p6a_life.md`、`p6b_life.md`、`p6c_blueprint.md`，默认就是主要交给
客户阅读的核心正文。到这些阶段会自动读取 `vedic_core_life_rendering.md`：先锁定
上游结论、最强反证和有效时间分辨率，再把十大板块组织成一条连贯的人生主线。
它不会删术语和反证来换取“人话”，也不会另建文件、跳过Skill规定的板块或启动
分析师剪辑模式。

补丁会区分四类产物：

- skill规定的Core完整报告（技术底稿 + 默认客户正文）；
- 明确激活后生成的分析师完整报告；
- 已合法进入QA阶段后的单题答疑；
- 明确盲问产生的全量扫描产物。

“把QA说得像人话”不会误触发完整分析师剪辑模式。普通QA仍使用所选skill规定的
文件名和目录：先明确回答，再解释盘面机制与真正改变结论的反证，随后描述最可能
的落地方式。只有确有价值时才给盘面相关的行动建议，不再默认追加现实权衡、决策
阈值或免责声明。skill要求的矩阵、正反双审、分盘交叉和聊天框可见过程仍保留在
规定的技术位置。

“生成报告／导出HTML”只选择既有Markdown的呈现形式，不授权改写或合并产物。
执行前必须检查打包工具实际会读取哪些文件；如果工具不支持指定的单一产物，
不得用技术主报告替代、把分析师报告冒充QA，或声称已经完成精确打包。

## 使用

普通Vedic分析无需额外粘贴提示词，直接调用相应skill。

Core运行到标准版十大板块或Pro版十大板块／生命蓝图时，不需要额外口令；
精确人话成文层会按阶段自动触发。分析师剪辑版仍是Core完成后的可选重组层，
只有明确激活时才生成。

当所选skill已经满足自身QA入口条件后，普通追问会自动采用咨询式成文层，
无需激活“印占咨询式整合模式”。纯技术追问可以保持简洁，不强制增加现实映射
和行动建议；普通咨询问答则默认采用明确、自然、温柔而坚定的占星师口吻。

需要默认的UC隔离盲审时，请在安装后新建的任务，或已经确认加载了本规则的
现有任务中使用：

> 按盲问全量扫描协议执行。UC可以存在，但不得参与盘面结论；完整扫描全部候选，找到强点后继续扫到终点。

Codex会根据 `AGENTS.md` 自动读取
`~/.codex/vedic_blind_qa_prompt.md`，无需每次手动粘贴全文。

本包当前随附盲问协议v1.3。它把“全量扫描”定义为决策相关候选全部进入
MD/AD矩阵，而不是把729行PD整表加载进上下文；月／日级、窄于完整AD或仍需
细分的候选，须先锁定全部PD合格集合，再以相同精度统一局部下钻。该能力依赖
新版 `vedic-calculator` 的原生PD与 `scripts/dasha_query.py`。本包不包含skills；
若接收方尚未安装兼容版本或PD校验失败，不得自行按比例补算，必须降级到AD分辨率。

如果答案已经在任务中出现，结果必须标记为“答案已知的回溯式全量盲审”，
但仍继续扫描，不因UC存在而停止。

只有需要证明答案在分析前从未泄漏时，才使用新的Codex任务和净化数据包，
并明确指定“防泄漏盲测”。

已有完整core报告，需要生成一份分析师剪辑版完整报告时，可以说：

> 激活印占咨询式整合模式。基于当前已选定并已经完成的vedic-core或vedic-core-pro报告，生成一份分析师剪辑版完整报告；不要重跑core，不要写成Q&A。

Codex会自动读取
`~/.codex/vedic_consultative_integration_prompt.md`。该模式把p系列技术底稿
剪辑成独立的 `consultation_analyst_edit.md`，只改变报告组织、表达、前事核对
和行动建议，不会覆盖Vedic skill的技术流程或UC证据边界。

新版分析师成文不再以可信度分类和风险说明开场，也不会把每个板块写成“可能A、
也可能B、请结合实际”。它先给全盘总判断和前事落地，再展开人物机制、领域联动
和时间线；真正影响结论的限制集中说明一次，建议必须来自盘面，而不是泛化辅导。

当前分析师协议为v2.3，进一步要求“直接、具体、写透”：抽象的结构、承载、能量、
课题或重组必须翻译成用户在关系、事业、金钱、家庭和时间线上实际会看见什么；
通俗不等于缩短，重要结论要用完整自然段讲清因果、表现和落地。强信号先给明确
判断，不用连续缓冲词和免责声明把答案写没。真正形成综合洞察时允许保留有盘面
依据、能被客户记住的金句，但不按章节凑数量，也不写万能鸡汤。

该模式按既有报告谱系工作：标准版先用p1至p4和appendix锁定纯盘面底表，
再读取p5a/p5b；Pro版先用p0、p2至p5c技术文件和appendix锁定底表，再读取
p6a/p6b/p6c。随后才在skill允许的范围内用现实材料做咨询适配。
成品会分开显示“盘面置信度”和“外部验证／现实适配状态”；前事吻合或不吻合
不能静默改写盘面置信度。

在Q&A选择题中，同样先锁定盘面评价标准，再按同一标准映射Offer A／B等现实
选项。选项事实可以合理改变最终推荐，但不能倒过来修改盘面标准和权重。
