# 宫位诊断框架

> 用途：core在Step 3宫位诊断时参考
> 每个宫位执行：管理者审计 + 租客审计 + 相位审计 + 硬件带宽(SAV条件展开) + 分盘交叉（如有，**必须遵循下方「分盘视角分离铁律」**）

---

## 分盘输入稳定性先决条件

任何D9/D10/D4/D5落宫、分盘内部宫主或房东判断，都先读取structured_data的
分盘边界审计。边界敏感分盘不得沿给定分钟的单点Lagna下定论；稳定不受影响的
行星分盘星座可以保留，但由分盘Lagna派生的宫位链必须分候选或降级。出生证来源、
直接计算成功和D1稳定都不能替代这项检查。旧数据无审计时标“未验证”，不默认为稳。

## 分盘视角分离铁律（所有 varga：D9/D10/D4/D5/D7/D12… 通用；引用任何分盘前必读）

分盘断语必须严格分两条线，禁混用、禁不标视角：

- **线A — 分盘内部宫主**：用【分盘自身 Lagna】推该盘宫主表。数据直接读 structured_data「分盘内部宫主表 + 尊贵度（线A）」段（calc 查表，❌ 禁自推）。
  记法：`D10-L10=Saturn，Saturn 落 D10-H*`。D10-L10 由 D10 Lagna 定，**不是**本命 L10。
- **线B — 跨盘参照**：本命行星保留其【D1 宫主职身份】，看它落分盘哪个宫。
  记法：`本命 L2/L11 主 Jupiter，在 D10 落 H9` —— L*/L* **必须显式标注是 D1 视角**。

**四条禁止**：
① 断言"X 是 H* 主"而不说是哪个盘（"Jupiter 是 H9 主" = 错）；
② "L*+L* 落 D*-H*" 而不标 L*/L* 是 D1 身份；
③ 直接拿 D1 宫主职跳到分盘结论；
④ 混用 D1 尊贵度与分盘内部尊贵度而不说明（分盘尊贵读 structured_data 分盘尊贵段）。

**冲突仲裁**：线A、线B 结论不一致 → 分别呈现，禁折衷成"综合来看"。
**输出结构**：逐星深度审计级分盘（如 D9 Step 2.1）走【线A/线B/综合】三段；概述级分盘（D10/D4/D5 概述）的颗粒度**以各版 SKILL 概述指令为准**——Pro 版走三段，开源版精简为线A/线B 各一句。（无论粗细，线A/线B 都必须显式标视角，不因精简而混用。）
**下游消费**：宫位诊断/专题/十大板块等任何下游步骤引用分盘结论（p3b 等）写正文时，必须**沿用其线A/线B标注**——禁止压平成 D1 宫主职、禁止"X是H*主"不标盘；分盘尊贵度用分盘内部值、与 D1 尊贵度分开标。

⚠️ D9 章节（core Step 2.1）的"D1身份带入D9=线B、D9是质量调整非属性翻转、D9弱不能美化"
   是本铁律在 D9 上的一个**实例**；此纪律同等推广到 D10/D4/D5/D7/D12 等**所有更小分盘**。

## 诊断四维度

### 1. 管理者（宫头星/宫主）
```
查看宫主的：
  P1身份 → 它是什么角色？
  去向(落宫) → 它去了哪个宫位？把这个宫的能量带到了哪里？
  P7尊贵度 → 它健不健康？
  P9 Shadbala → 它有没有力量执行？
```

### 2. 租客（宫内行星）
```
查看宫内星的：
  自带属性 → 吉星进驻=加持，凶星进驻=干扰
  合相情况 → 多颗星同宫=事务繁忙
```

### 3. 相位（谁在看这个宫位）
```
查看哪些行星对此宫位有相位（P10）：
  吉星相位 = 外部加持（保护/增益）
  凶星相位 = 外部压力（冲突/限制/放大）

  相位合成铁律（吉凶相位并存时，沿用"方向/执行分层"模式）：
    分层陈述——吉定结果保底、凶定过程摩擦
    ❌ 禁止择一而论（只报木星保护 或 只报土星限制）
    ❌ 禁止对冲抵消（"一吉一凶互相抵消"）
  多星相位 → 禁止笼统写"受多方面外部影响"，必须按上述铁律
    把每颗相位星归入"结果保底/过程摩擦"两层逐星陈述
```

### 4. 硬件带宽（SAV）— 辅助维度

⚠️ SAV读取铁规（唯一定义，各 skill 引用处逐字同句）：引用任何宫位SAV值，必须从structured_data「宫位映射」表读取；禁止读「原始值（按星座）」表或自行计算sign→house映射；输出标注格式 N宫(Sign)SAV=X。

```
SAV是辅助确认指标。展示与提及规则全 skill 统一为单点：仅极端值（>32 或 <20）时在数据表列出/在叙事中提及（见 SKILL.md 输出模板与关键原则6），中间值不展开。四档参考：
  SAV > 32 = 溢出（资源充裕）
  SAV 26-32 = 平稳（正常运作）
  SAV 20-25 = 紧张（需要额外努力）
  SAV < 20 = 匮乏（结构性不足）

特殊：凶宫(6/8/12) SAV低 = 反而是防火墙（贼进空屋）
      凶宫(6/8/12) SAV高 = 反转效果（破坏资源充足）
  适用边界：本条仅指该宫灾祸类事件的频率/强度层（6=疾病/官非、8=突变/危机、12=损耗），
    不适用于该宫正面义项（6=竞争/服务力、8=遗产/研究、12=海外/灵性）与掌宫行星的资源评估——
    正面义项与掌宫资源仍按上方四档正读（低=匮乏、高=充裕），
    见p1_p12 P4适用边界与下方「SAV 不计入正/负面主计数」说明（凶宫防火墙仅属灾祸事件层）
  ⚠️ 防火墙/反转是**解读逻辑层**，不受 SKILL「非极端 SAV 行必删」展示门槛约束——凶宫 SAV 落 20-25「紧张」区间也照常参与防火墙/资源解读，只是不单列进 SAV 展示行；展示门槛(仅极端才列表)与解读逻辑分属两层
```

## 宫位评级

```
创始人模式：宫主强+宫内有吉星+吉星相位 → 自主掌控
创始人模式（带阻力）：宫主强+凶星相位 → 仍自主掌控，但过程带阻力（吉凶相位并存时按相位合成铁律分层陈述）
经理人模式：宫主中等+正常相位 → 正常运作
吉祥物模式：宫主弱+有吉星相位 → 有贵人帮但自己弱
飘萍模式：宫主弱+无吉星+凶星相位 → 该领域缺乏根基
（SAV极端值可作为模式判定的辅助确认，但不作为主要判据）
```

## 多阶段事件推导

大事件不是单一时间点，而是分阶段展开，每个阶段由不同宫主的Dasha触发：

| 事件 | 阶段1 (启动) | 阶段2 (落地) | 阶段3 (收益) |
|------|-------------|-------------|-------------|
| 结婚 | L7 (关系确立) | L9/9宫星 (法律确认) | L11 (社会公开) |
| 换工作 | L10 (机会/决定) | L6 (入职/竞争) | L11 (收入到位) |
| 买房 | L4 (动念/看房) | L2 (出钱/签约) | L4+D4 (入住) |
| 出国 | L9/L12 (决定) | L12 (离开) | L4 (安家) |

⚠️ 上表是**候选检查表**，不是固定触发器映射。必须先完成领域轴、形态轴、时间轴，
再判断哪些宫主在本盘里通过合相/互视/互溶、节点定位链或相关分盘构成同一事件链。
没有结构连接时不得为凑齐三阶段强行套表；同一个AD/PD事件簇可以承载多个阶段，
也可以同时承载多个各自有独立结构连接的现实事件。

### 婚姻时间推导（三阶段模型）

现代婚姻是过程不是瞬间。先分开结算三轴，再识别可能的阶段：

```
领域轴 — L7/DK/UL、关系Karaka与D9回答“关系领域是否被点名”
形态轴 — D9-L7承载、关系主星状态、2/8/12宫阈值、保护与受损反证回答
          “形成/正式化/维持/重组/中断风险”；领域活跃不自动等于结婚
时间轴 — MD定背景、AD定阶段、PD才可进入月级候选

可能阶段（按本盘结构选用，不是必经清单）：
  关系启动或确认 / 法律或资源正式化 / 社会公开 / 共同生活 / 后处理或重建

⚠️ Venus作为自然关系Karaka必须检查，但不能单独定结婚；L7当值也只能先定关系领域
⚠️ 多个阶段可落在同一事件簇，也可跨相邻AD/PD；节点→定位星接棒时必须审计handoff cluster
⚠️ 输出应说明“领域+形态候选+实际分辨率”，不要把单一宫主当值写成确定婚姻事件
```

### 大运正负面判断规则

大运星的正负面不是"感觉"，是有明确判定条件的：

⚠️ 节点例外：大运/小运星为 Rahu/Ketu 时，本节正负面条件不可计算（节点无掌宫身份/自身尊贵度）——改用 p1_p12「Dasha速查表节点专用正负面条件子表」（P7.4）；速查表节点行"P1身份"列填"—"、"尊贵度"列填定位星状态。

⚠️ **P1身份读 structured_data「功能身份」表 primary_role**（禁自判主身份）；一星身兼吉凶宫主（is_dual=是）→ 正/负面条件1 **按主身份计一次、不双计**（MT 已定主，兼管的另一宫作叙述注明、不另计对侧）。

#### 正面条件（满足≥2条→判定为正面）
```
1. P1身份=吉角色（Core-Driver / Yogakaraka / Faithful）
2. P7尊贵度≥友方（Friend/Own/Moolatrikona/Exalted）
3. P9 Shadbala≥120%
4. 落在吉路（1/4/5/7/9/10宫）
5. Vargottama或Dig Bala加成
```

#### 负面条件（满足任一即标注风险）
```
1. P1身份=凶角色（Destroyer管8/12 或 Growth-Hacker管6）
2. P2受损（燃烧/落陷/败相）——⚠️ 落陷读 structured_data「落陷解除」表：「大运不计落陷」=是（独立解除式≥3，见 p1_p12 P7）则**不计落陷**；燃烧/败相仍计。其余档（单式、多重、有缓冲）仍计落陷，叙述注明"有解"或"有托底"
3. 落在凶路（6/8/12宫）且无VRY补救
4. P9 Shadbala<100%
5. 与凶星紧密合相（<5°）
```

> ⚠️ **SAV 不计入上述正/负面主计数**（原正面第5条 SAV≥28、负面第5条 SAV<25 已移除）——避免非极端阈值 28/25 让辅助指标与 P1身份/P7尊贵度等权。SAV 是**辅助确认、不定方向**：仅当达**极端值(>32 或 <20)** 时，作为"方向已由上述条件判定后"的**叙事备注**（不进档位计数、不加减档位），不改变正/负面归类。凶宫「SAV低=防火墙」仍仅属灾祸事件层（见 §4 硬件带宽）。

#### 判定逻辑（按顺序判定，首个命中即停——互斥、全覆盖）
```
1. 危机期：正面=0 且 负面≥2 → 需谨慎/有风险（最严条件先判）
2. 困难期：正面<2 且 负面≥1 → 该领域面临挑战
3. 混合期：正面≥2 且 负面≥1 → 发展中伴随压力
4. 正面期：正面≥2 且 负面=0 → 该领域顺利/上升
5. 平淡期：以上都不中（即 正面<2 且 负面=0）→ 无显著信号，该领域平稳过渡（兜底）

⚠️ 必须从1往5顺序判，首个命中即定档；禁止乱序读表。
```

### Dasha事件优先级（多事件同期激活时的排序规则）

当用户问"先发生A还是先发生B"时（如"先换工作还是先结婚"），必须用以下规则排序：

```
规则1：实际Dasha层级时序优先
  先比较AD；若两个候选落在同一AD且问题要求月份/季度内先后，必须下钻到原生PD。
  只有同层窗口不重叠且形态轴均支持落地时，才可据时序判断先后。
  例：L10的AD在2026.3-2027.1，L7的AD在2027.1-2027.8
  → 换工作(10宫)先于结婚(7宫)

规则2：同一PD/同一交接簇内不强排一对一
  同一枢纽若连接多个领域，可以同簇并行显化；分别检查每项事件的领域连接与形态证据。
  MD只定背景，不能凭“大运主管宫”武断宣布哪个现实事件先落地。

规则3：行星力量只定显化强弱，不定钟表先后
  Shadbala/尊贵度可说明哪个主题更显眼、更能承载，但不能替代PD时序。
  同一PD内若没有独立第二时间系统或可复核过运分开两者，输出“并行/顺序未定”，禁止假精度。

规则4：多阶段事件的阶段分辨
  参照上方"多阶段事件推导"表：
  很多时候A和B并非互斥——可能A处于阶段1（启动），B处于阶段2（落地）。
  必须分辨用户问的是"启动"还是"完成"。
  例："换工作"可能阶段1(机会出现)在2026，阶段2(正式入职)在2027。

输出格式：
  "根据Dasha时间线：
   [事件A]的阶段窗口在[AD]，月级候选在[PD/PD缺失]
   [事件B]的阶段窗口在[AD]，月级候选在[PD/PD缺失]
   [若同层窗口可分离]时间上[A]先于[B]；
   [若不可分离]两者属于同一事件簇，盘面不足以可靠区分先后。"
```

⚠️ **禁止**：不能用"感觉"、宫位重要性、Shadbala或一般经验替代真实AD/PD边界排序。
