# Prashna Q&A 追问规则

> 追问沿用原盘，不换时间挑答案。标准、Tajika、KP 的计算和结论权限保持隔离；
> 跨栈 Q&A 只并列解释，不拼票。

---

## 1. 先判追问还是新问题

追问必须仍围绕原盘的同一个可观察结果，包括：

- 澄清术语、来源支持级、输入稳定性或某条证据；
- 细化推力、阻力、转机、现实条件和时间副层；
- 细化三层：指标星能不能履行（能力层）、指标星在做什么（意愿层）、两边环境（账本）；
- **在原结果上补限定语**：谁主动、私下还是公开、在家还是在外、是否在某一天（按 §4"追问补条件"处理）；
- 解释 Tajika Yoga 或 KP promise／gate；
- 比较已经生成的标准、Tajika、KP 为什么一致或不同。

以下属于新问题，回 `SKILL.md Phase 0`：

- 对象、目标结果或待执行行动改变；
- 新事实使原问题的结果语义发生实质改变；
- 从可观察结果改问秘密动机、逐字心理或长期人生趋势；
- 从原事项跳到另一个独立事项。

补限定语不是新问题：问"会不会见面"之后补"必须由对方主动""只算私下"，可观察的事件仍是见面，
只是多了条件，沿用原盘检验条件。换成另一件事（从"会不会见面"改问"会不会在一起"）才是新问题。

时间经过本身不是新问题门槛；不得使用 24 小时、3 个月等固定阈值。

只换问法、不换对象和目标结果，不算新问题。同一段关系里问“会不会联系”“能不能
复合”“我挽回能不能成”属于这种情况：沿用原盘结论作答，不换规则重判
（见 `question-taxonomy.md` §2.5）。

追问时不重复安抚，除非用户表达了新的情绪；安抚不改结论（见 `SKILL.md` Phase 6）。

## 2. 当前盘解析

必须先取得当前盘的明确目录或由当前对话唯一确定：

- 标准／Tajika：`prashna_<yyyymmdd_HHMMSS>_<label>/`
- KP：`kp_horary_<yyyymmdd_HHMMSS>_<label>/`

若当前对话存在多张同类盘且“这个盘”不能唯一解析，先让用户指定，不扫描所有
`prashna_*` 或 `kp_horary_*` 猜测。

输入纠错不算重起。若发现原盘使用了处理时刻、错误地点或丢失秒数，只使受影响的
下游产物失效，以原始问题时刻和实际地点重建，不把纠错盘解释成第二次占问。

## 3. 四种 Q&A 路由

| 模式 | 允许读取 | 输出权限 |
|---|---|---|
| 标准追问 | 当前 `structured_prashna.md`、`prashna_judgment_*.md`、`timing_overlay.md`、同目录标准 Q&A | 解释标准层账本、内部档（不对用户说档名）和时间副层 |
| Tajika 追问 | 当前标准目录上述文件＋`tajika_overlay.md` | 解释接触过程；不得改标准三档 |
| KP 追问 | 当前 `structured_kp.md/json`、`kp_judgment_*.md`、同目录 KP Q&A | 解释 KP promise、RP、gate、timing；不得读取标准目录 |
| 跨栈比较 | 用户或当前对话明确关联的一个标准目录和一个 KP 目录 | 分栏解释三栈、一致点、冲突点；不得投票或生成混合结论 |

任何模式都禁止读取：

- `user_context.md`；
- 其他未明确选中的 Prashna／KP 目录；
- core/love/career/synastry/rectifier 等其他 skill 产物；
- 提问盘生成的本命式 Dasha、SAV、完整分盘或 transit。

## 4. 标准与 Tajika 追问

### 标准追问

按判读单已显示的 `rule_id`，以及核对区的能力层、意愿层与限定语结论回答。每个判断都须回查标准白名单字段
（含"宫主能力与连接"表）。来源支持级
A／B 只说明题型来源覆盖，不是概率，也不自动决定内部档。追问时按判读单讲事情怎么走，
不在给用户看的回答里说出档名。

口吻和含义来源同判读单：按 `judgment-writing.md` §1 的口吻写，术语第一次出现紧跟白话，篇幅按追问
实际需要，不套判读单字数；宫义、星义、
星座性质只取该文件 §2 的六类来源（宫义见 `house-meanings.md`）。判读单没展开的盘面细节可以补讲，
挂在账本条目、能力层、意愿层或背景事实旁；"指标星在做什么"按 `judgment-writing.md` §3 的五步展开。
补讲不许加码：不让背景、意愿层去改账本方向。

追问不改档：倾向以原判读单核对区的内部档和账本为准，回答里不另起结论。若追问中发现原账本
读错（宫位、标签或规则适用错了），这是纠错，不是 Q&A：按 §2 输入纠错同一口径，只让受影响的
下游产物失效，回 `SKILL.md` Phase 4 重做账本与内部档并重写判读单，向用户说明是纠错而非重新
占问；不在追问回答里直接改口。

**分类更正**：首次判读把题型归错（如"对方会不会主动约我见面"被归进"合作、另一方会否配合"）也属纠错，
按 `question-taxonomy.md` §2.5 的例外，在同一张盘上按正确题型重建一次账本，核对区标"分类更正"。

**追问补条件**（如"必须由对方发起""只算私下见面"）：不重建账本、不改档；按 `judgment-rubric.md` §2.3
检验这个条件，用意愿层（指标星在做什么）回答它成立与否、有多强。条件是必要条件且不成立时，回答
"按这个条件不能"。用户在追问里点名的盘面组合，必须逐条回答它按出处怎么读、在本题里起什么作用
（`judgment-writing.md` §3 第 6 条）。"由某人主动"这类条件读原盘的行动链（`judgment-rubric.md` §2.5）。

**追问"会不会转成行动""谁会主动""靠什么连上"**：直接读原盘 `structured_prashna.md`"行动者视角（转宫）与
行动链"和"征象星串联"表回答，不重起盘、不改档。别人的动作从那个人的宫起算（`question-decomposition.md`
第 3 节）；同宫、照射之星按 `house-meanings.md` 第 5 节"带来什么、这题要不要、有没有力送到"讲。原判读单没写
行动链（10-29 之前生成）的，按同一张盘补读，说明是补讲，不是新结论。

**用户提出自己的读法**（如"Mars 与 Lagna 主同宫、又照 7 宫主，行动把两边连上了"）：先按出处判断这个读法
属于哪一类，正面回答，不回避、也不顺着改档：

1. 读法对应的是本题账本规则，原判漏算或算错 → 属纠错，按上文回 Phase 4 重做；
2. 读法有出处，但属于能力层、意愿层、行动链或宫义（不计分）→ 按出处讲清它说明了什么（例如"对方起意的
   星把两边连上了，但它落陷，方式受损"），以及为什么不改变成败档；
3. 读法在出处里找不到或出处读法不同 → 讲清出处里这个配置怎么读，两层宫义不一致时并列。例：把本盘 3 宫
   读成"对方的主动"——本盘 3 宫是提问人自己的勇气，对方的主动看对方起第 3 宫（本盘 9 宫）。

不论哪一类，都要说清出处、在本题里起什么作用；不能为了让用户满意改档。

输入敏感性须拆开：

1. 哪个字段临界；
2. 本题账本是否实际消费该字段；
3. 主结论使用的 D1 结构是否稳定。

### 后加 Tajika

用户明确要求 Tajika 时，沿用标准盘的原始秒级时刻、地点、问者星和事项星，运行：

```bash
python scripts/build_tajika_overlay.py \
  --datetime "<原盘 YYYY-MM-DD HH:MM:SS[.ffffff]>" \
  --lat <原盘 lat> --lon <原盘 lon> --tz "<原盘 IANA>" \
  --querent-lord <Lagna lord> --matter-lord <事项宫主> \
  --out-dir "<当前 prashna_* 目录>"
```

不得重跑或覆盖 `structured_prashna.md`，也不存在 `--enable-tajika`。
查表题、不判题，以及问者星与事项星为同一颗时不运行，按 `tajika-optional.md`
用一句白话说明，不拿 Karaka 或其他宫主顶替。

## 5. KP 追问与后加 KP

已有 KP 盘的追问沿用原 KP number、判盘时刻、地点和 topic，不重新选号码。
先核对原盘的 outcome scope。`love-materialization` 的结论只回答是否建立明确、
双方确认并持续推进的恋爱关系；不得外推为是否会恢复联系、互动回暖或恢复暧昧。
若原问题只是这些低门槛结果，却误用了 `love-materialization`，保留原计算文件作为
高门槛题型结果，但明确宣布它不能回答原低门槛问题；不得据此改判或重算。

标准盘之后想查看 KP，不是把 KP 字段追加到原盘，而是新建独立 KP 栈。必须：

1. 用户亲自给出 1–249；
2. 记录开始判断 KP 问题的秒级时刻和实际地点；
3. 让用户确认同一个可观察结果对应的 outcome scope；
4. 只有 outcome scope 与已支持 topic 完全一致时才起盘；不一致时按
   `kp-optional.md`“不收时的出口”回答，不起盘；
5. 写入独立 `kp_horary_*` 目录。

这不允许 KP 回写或改判标准结论。

## 6. 宽泛跨栈追问

用户问“整体怎么看”“三个体系怎么说”“为什么不同”时，若相关结果均已存在，按固定
结构回答（这里的"三栈"指标准、Tajika、KP，不是标准层内部的能力、意愿、环境三层）：

```markdown
## 标准层
<来源支持级、内部档（偏成／持平／偏不成）与强度、规则账本摘要、能力层与限定语结论>

## Tajika
<直接接触、传递/援助/阻断、timing 状态；与标准层时间不互相校正>

## KP
<独立 promise 状态、正反宫命中、gate、timing 状态>

## 一致与冲突
- 一致点：<逐项列出>
- 冲突点：<逐项列出>
- 边界：三栈不投票；标准层仍是标准结论，KP 保持独立。各栈时间来自不同体系，
  不互相校正，主答案以标准判读单 §四 为准。
```

跨栈比较只能在 Q&A 协调层读取明确关联的文件。默认只在聊天显示；用户要求保存时，
写入其明确授权的共同私人父目录，文件名 `qa_compare_<label>.md`，不得写进任一栈
目录造成后续偷读。

## 7. Timing 追问

- 标准层：偏成／持平档读 `timing_overlay.md` 作答；偏不成档不给时间（含能力层否决"能力不足"），
  持平·盘面未给方向也不给时间。偏成／持平档的盘当时没跑时间副层的，用原盘时刻、地点补跑
  `build_timing_overlay.py`，不重起盘；
- 问题自带日期（如"11 月 15 日当天"）：时间副层只能说盘面节奏和最近的触发日，判断不了是否恰好落在
  那一天；如实说明，不把触发日说成那一天，也不因日期对不上改档；
- Tajika 仅在主星直接 Itthasala 时显示 `度差 × 12 日` 原典比例候选。它和标准层
  时间来自不同体系，不互相校正，主答案以判读单 §四 为准；
- KP 只在正向 promise、逆行门清空、node 路径完整和 RP／period／transit 条件满足
  时显示候选；
- 一个栈没有 timing 时，不得借另一个栈的日期冒充本栈答案。

## 8. Q&A 文件

单栈追问写入当前栈目录的 `qa_<主题短标签>.md`：

```markdown
# Q&A：<主题>

**关联盘**：<精确目录名>
**追问时刻**：<YYYY-MM-DD HH:MM:SS>
**追问类型**：[澄清／细化／拓展]
**目标栈**：[标准／Tajika／KP]

## 问
<用户原问>

## 答
<白话解释>

## 引用
- <文件> §<段>：<字段或结论>
```

多轮同主题可追加；不同主题拆文件。Q&A 不改写原结构盘或原判读单。

**旧版判读单**：2026-10-29 三层改版前生成的判读单，核对区没有能力层、意愿层，数据里也没有"宫主能力与
连接"表。追问时先说明这是旧版；能直接回答的照常回答。用户要按新版重写，由用户用原盘时刻、地点重新
起盘生成（这是版本更新，不是重新占问），不在追问里替旧判读单改档。
